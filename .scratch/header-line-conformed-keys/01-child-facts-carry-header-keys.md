# Child-grain facts must carry the crash header's dimension keys

Status: ready-for-human
Category: enhancement
Raised: 2026-09-21 (Phase 11, landing-zone runbook)

> *This was generated by AI during Phase 11 and is a handover for later work.*

## Problem

The model is a header/line design that breaks Kimball's header/line rule. The crash is the
header, and persons and vehicles are its lines. Only `fact_crashes` carries `location_key` and
`factor_group_key`. `fact_persons` and `fact_crash_vehicle` reach those dimensions only
indirectly, through `collision_key` → `dim_collision`, which has no relationship to them.

Consequences:

- **Security leak (live in Prod).** RLS role `Borough_Reader` (`dim_location[borough] = "BROOKLYN"`)
  filters `fact_crashes` to 506,806 rows, but `fact_persons` (5,984,110), `fact_crash_vehicle`
  (4,551,002) and `bridge_crash_factor` (1,648,599) come back **unfiltered**. Verified via
  XMLA role impersonation on 2026-09-21.
- **Analytics gap.** Persons and vehicles can't be sliced by borough, zip or contributing factor
  without per-query DAX lookups.
- **DAX sprawl.** Every location- or factor-based role would need hand-written `IN CALCULATETABLE(...)`
  filters on `dim_collision` and `dim_factor_group`. That approach was prototyped and rejected in
  Phase 11 because it hides a model defect behind DAX.

## Kimball basis

> "With header/line schemas … all the header-level dimension foreign keys and degenerate
> dimensions should be included on the line-level fact table."
> — [Header/Line Fact Tables](https://www.kimballgroup.com/data-warehouse-business-intelligence-resources/kimball-techniques/dimensional-modeling-techniques/header-line-fact-table/)

See also [Design Tip #95](https://www.kimballgroup.com/2007/10/design-tip-95-patterns-to-avoid-when-modeling-headerline-item-transactions/),
which names reaching the header's dimensions through the header table as a pattern to avoid.

## Proposed change

Add `location_key` and `factor_group_key` (`BIGINT`) to `fact_persons` and `fact_crash_vehicle`,
resolved from the crash header during load. `date_key` is already present on both. The result is a
fact constellation: about four new single-direction, many-to-one relationships and no ambiguous
paths. Give each fact its own diagram layout for readability.
