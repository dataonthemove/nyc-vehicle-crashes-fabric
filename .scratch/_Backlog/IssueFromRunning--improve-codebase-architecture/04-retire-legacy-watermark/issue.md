# Retire legacy `dbo.etl_watermark` and fix the watermark guidance

Status: needs-triage
Category: bug
Raised: 2026-11-23 (`/improve-codebase-architecture` review)

> *This was generated by AI during a CC architecture review and is a handover for later work.*

## Problem

Only one module really owns the **Watermark**: Fabric Notebook `nb_etl_watermark` (seed /
advance / read), which writes Delta table `etl_watermark` in the landing Lakehouse. It is read
by `pl_cdc_NYC_Crashes_Landing`. No `usp_load_*` proc reads or writes a watermark.

The guidance that agents load says otherwise:

- **CC skill `warehouse-dml`** (`~/.claude/skills/warehouse-dml/SKILL.md`, lines 13–19 and 35)
  states: "Single authoritative watermark store: `dbo.etl_watermark` in the Warehouse. There is
  no Delta-layer watermark". This is wrong, and it steers agents to write to the legacy table.
  The same skill says "prefer MERGE", but no proc uses MERGE; all are insert-if-absent.
- **CLAUDE.md** (Architecture Conventions, Watermark) still says `dbo.etl_watermark` "stays in
  place and authoritative until the ingestion move (landing-zone Phase 6) cuts over".
- **Against that:** ADR-0002 and `Context/environment-reference.md` describe the Warehouse table
  as legacy with 0 rows.
- The table is still deployed, from `.../dbo/Tables/etl_watermark.sql`.

## Proposal

1. Confirm that landing-zone Phase 6 cut over, using ADR-0002 and
   `Context/landing_zone_runbook_results.md`.
2. Rewrite the watermark section of CC skill `warehouse-dml` so it points at `nb_etl_watermark`
   as the only interface, and align its MERGE guidance with the actual insert-if-absent pattern.
   The skill lives in the `~/.claude` config repo, not this repo.
3. Update the CLAUDE.md watermark bullet: drop the "until cutover" clause and mark the Warehouse
   table as retired.
4. Remove `dbo/Tables/etl_watermark.sql` from the Warehouse item definition, and drop the table
   in each stage. Drop first, then check `sys.tables` and the row counts after the deploy.

## Acceptance criteria

- [ ] No skill, CLAUDE.md line or memory describes `dbo.etl_watermark` as authoritative.
- [ ] The Warehouse item definition no longer contains `etl_watermark`, and the table is absent
      from Dev, Test and Prod.
- [ ] A CDC run of `pl_cdc_NYC_Crashes_Landing` still reads and advances the Delta watermark.
