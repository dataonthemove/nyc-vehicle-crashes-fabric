# Business code lists become dimension flags

## Problem

Some measure DAX decides code-set membership inline, for example:

- the role exclusions in `Persons Involved`;
- the Ejection value lists;
- the Driver License status lists.

`2_dev/4_Model/SEMANTIC_MODEL.md` (lines 122–142) restates the same lists. The classification
can't be reached from SQL or used as a slicer, and each copy has to be kept in step by hand.

Related: `Geocoded Crash %` tests `Latitude <> 0`. Since `usp_load_fact_crashes` (lines 104–109)
NULLs out-of-box points, including (0,0), that test is redundant and its denominator semantics
may have shifted.

## Proposal

Classify each code once in the Warehouse as a boolean dimension attribute, e.g.
`dim_person.is_ejected`, ideally inside the cleansed source view from issue 01. Measures then
filter on the flag, and `SEMANTIC_MODEL.md` references the flag instead of listing the values.

## Open questions

- Under ADR-0007, new columns are the Additive class. If a measure's numbers move, it becomes the
  Logic class and needs a release note before Prod.
- Low urgency: worth doing only alongside issue 01, or when a list next changes.

## Acceptance criteria

- [ ] Each code list exists in one SQL location; measures reference the flags.
- [ ] Measure results in Dev are unchanged, or the differences are explained and noted.
- [ ] The `Geocoded Crash %` denominator is reviewed against the lat/long cleanse.
