## Problem

The 15 model relationships are defined in
`2_dev/4_Model/NYC_VehicleCrashes_Semantic.SemanticModel/definition/relationships.tmdl`, then
restated by hand in three more places:

- the `RELS` list in CC skill `dax-smoke-test` (lines 83–99);
- the DAX `_expected` table in the same skill (lines 217–233);
- the count in `2_dev/4_Model/SEMANTIC_MODEL.md` (line 48).

The skill says "edit all three". Add a relationship and forget one copy, and the smoke test
either fails for the wrong reason or passes against a stale list.

Related findings:

- The skill sits at user level (`~/.claude/skills`), although it is entirely project-specific.
- It cites `.scratch/header-line-remodel/spec.md`, which now exists only under `_Archive`.

## Proposal

Add a skill step that parses `relationships.tmdl` (from/to table and column, cross-filter,
`relyOnReferentialIntegrity`) into the expected list. The Spark key checks and the DAX
`INFO.VIEW.RELATIONSHIPS` comparison both use that parsed list. The smoke test then checks
**git vs deployed model** instead of comparing against a hand copy.

Also consider moving the skill into the project at `.claude/skills/`, and fixing the archived
spec path.

## Acceptance criteria

- [ ] No hand-maintained relationship list remains in the skill. `SEMANTIC_MODEL.md` either
      references the TMDL or drops the count.
- [ ] Adding or removing a relationship in TMDL needs no skill edit for the smoke test to stay
      correct.
- [ ] A smoke-test run in Dev passes.
