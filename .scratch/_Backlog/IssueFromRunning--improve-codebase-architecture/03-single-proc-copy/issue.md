## Problem

Each of the 12 `etl.usp_load_*` procs exists twice:

- the authoring notebook `2_dev/3_Transform/*.Notebook/notebook-content.sql`;
- the Warehouse item definition `2_dev/0_Storage/0_NYC_VehicleCrashes_Warehouse.Warehouse/etl/StoredProcedures/*.sql`.

The table DDL follows the same pattern: `2_dev/1_DDL/0{1,2}_*.Notebook` and `.../dbo/Tables/*.sql`.

On 2026-11-23 all 12 proc bodies and all 12 tables matched, so the copies have not drifted. The
cost is that every change has to be made twice in the same commit. That guard is only a CLAUDE.md
rule and a memory, not something the repo structure enforces. Running the notebook also hides a
stale item definition, so a green validation says nothing about the copy that gets deployed.

One gap: `dbo.etl_watermark` has an item definition but no DDL notebook (see issue 04).

## Proposal

Make the Warehouse item definition the single source of each proc body. The notebooks keep:

- the markdown rationale;
- an `EXEC` cell plus a verify cell.

One-time backfill cells move to a scripts folder, e.g. `ops/backfills/`. Today those are
`11_ETL_fact_persons` Cell 3 (lines 143–183) and `12_ETL_fact_crash_vehicle` Cell 3 (lines
149–170). The same could later apply to the DDL notebooks.

## Open questions

- This reverses the CLAUDE.md convention that "the notebook is the source of truth". Record the
  change as an ADR if adopted.
- Is applying a proc change to Dev through Source Control Update All on the Warehouse item
  reliable, without running the notebook? Warehouse deploys have failed on live tables and once
  wiped Test (2026-09-28), so trial a single proc first.
- Is the notebook still worth keeping as a rationale document, or would a markdown file beside
  the item definition serve better?

## Acceptance criteria

- [ ] No proc body exists in a notebook; each exists only under `etl/StoredProcedures/`.
- [ ] A trial proc change reaches Dev through Update All, and reaches Test through the deployment
      pipeline, with row counts verified.
- [ ] CLAUDE.md and the memory file `warehouse_procs_duplicated_in_git.md` are updated, and an
      ADR records the decision.
