# Line facts never load persons or vehicles that arrive after their crash

Status: needs-triage
Category: bug
Raised: 2026-09-25 (header/line spec review)

> *This was generated by AI during the header/line spec review and is a handover for later work.*

## Problem

The incremental guard on `fact_persons` and `fact_crash_vehicle` skips a source row when **any** row
for its crash is already loaded (`WHERE NOT EXISTS … tgt.collision_key = dc.collision_key`, e.g.
`11_ETL_fact_persons` line 93, `12_ETL_fact_crash_vehicle` Cell 3 note). The guard is at crash grain,
but these facts are at person and crash–vehicle grain. If the source adds a person or vehicle to a
crash after that crash's first load, the new row is never picked up. Nothing reports it; counts just
drift below the source.

The header/line remodel (`.scratch/header-line-remodel/spec.md`, D2) re-keys the guard to
`collision_id` but keeps crash-grain semantics, so it does not fix this.

## Direction

Key the guard on the line's own business key — the source person id / vehicle id — not the crash.
First measure whether it happens: compare Lakehouse vs Warehouse row counts per `collision_id`.
