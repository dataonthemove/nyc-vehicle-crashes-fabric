# Driver License Status mixes two code sets

Status: needs-triage
Category: data-quality
Raised: 2026-10-12 (measure-list review of the Dev semantic model)

> *This was generated by AI from a conversation and is a handover for later work.*

## Problem

`Dim Driver`[Driver License Status] (Warehouse `dim_driver.driver_license_status`) carries two source
code sets side by side. Vehicle counts from the Dev model on 2026-10-12 (`execute_dax_query`):

| Code set | Values (vehicles) |
|---|---|
| Descriptive | Licensed 2,018,943 · Unlicensed 44,164 · Permit 20,747 |
| Abbreviated | VAL 10,014 · NOT_APP 217 · NONE 162 · UNK 150 · SUS 126 · APP 44 · EXP 31 · REVOKE 29 · SURRENDER 7 · CANCEL 6 · MILI 3 · HPRV 1 |
| Blank | 2,456,358 |

`etl.usp_load_dim_driver` loads the value as `NULLIF(TRIM(...), '')`, with no standardisation.

## Why it is doubtful

The payoff is small. The abbreviated set is ~10.8k vehicles, about 0.5% of vehicles with a known status. Only
~330 rows (NONE, SUS, REVOKE, EXP, CANCEL) would plausibly move into "Unlicensed", which shifts
`Unlicensed Driver %` by about 0.01–0.02 points. Until then that measure uses a denominator of
Licensed/Unlicensed/Permit only, so the abbreviated rows are excluded rather than miscounted.

## Cost if pursued

- **Mapping decision first.** VAL→Licensed and NONE→Unlicensed are clear. Decide whether
  SUS/REVOKE/EXP/CANCEL/SURRENDER map to Unlicensed or to a new "Invalid" value. The meaning of
  APP/NOT_APP/UNK/HPRV/MILI is unknown, so check the NYC Open Data dictionary.
- **4 code locations, kept identical.** The same `CASE` goes in `etl.usp_load_dim_driver` and in the
  `driver_key` lookup join of `etl.usp_load_fact_crash_vehicle`. Each exists as an authoring notebook
  (`07b_ETL_dim_driver`, `12_ETL_fact_crash_vehicle`) and as a Warehouse item definition. Change all
  four in one commit.
- **Backfill.** Remapping in place creates duplicate attribute sets in `dim_driver`, which double
  fact rows through the lookup join (same trap as the Vehicle Model Year fix,
  `.scratch/_Archive/measure-readiness-fixes/`). Rebuild `dim_driver` + `fact_crash_vehicle`
  (4.55M rows), or repoint `driver_key` and delete the duplicates.
- **Promotion.** Dev → Test → Prod with the Warehouse in the deployment. Verify row counts after
  each stage, then run `/dax-smoke-test`.
