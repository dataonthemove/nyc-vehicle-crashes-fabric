# Transform procedures never propagate source-row updates

Status: needs-triage
Category: enhancement
Raised: 2026-09-21 (Stage load grilling)

> *This was generated by AI during the Stage load grilling session and is a handover for later work.*

## Problem

Every `etl.usp_load_*` procedure except the date dimension inserts only rows whose business key is
absent (`NOT EXISTS`). Ingest merges updates into the Delta tables, but a crash, person or vehicle
row that Socrata later corrects (injury counts, contributing factors) never reaches the Warehouse.

## Context

Deliberately out of scope for the first Stage load pipeline (`.scratch/stage-load-pipeline/spec.md`).
The operator believes source updates are rare, so measure the rate before building a MERGE: count
Delta rows whose `_load_timestamp` changed on an existing key.
